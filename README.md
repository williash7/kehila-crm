# לוח בקרה קהילתי

אפליקציית ניהול אנשי קשר, תרומות ואירועים לארגון קהילתי — mobile-first, בעברית, בלי שרת ובלי עלות.

זו **גרסה גנרית**: אין בקוד שום שם ארגון, עיר או כתובת גיליון. כל משתמש מגדיר את הארגון שלו פעם אחת באשף פתיחה, ומחבר גיליון Google פרטי משלו. אותה אפליקציה משרתת כמה ארגונים שרוצים, וכל אחד רואה רק את הנתונים של עצמו.

## מה יש בפנים

- **דשבורד** — סיכום תרומות, זמני שבת, אירועים קרובים, המלצות ליצירת קשר
- **אנשי קשר** — חיפוש, מיון, כרטיס פרופיל, היסטוריית תרומות ומפגשים, מיזוג כפילויות
- **מפה** — סיכה לכל איש קשר לפי כתובת (Leaflet + OpenStreetMap, בלי מפתח API)
- **תאריכים אישיים** — ימי הולדת (לועזי ועברי) ויארצייטים, עם רשימת "קרובים" בדשבורד
- **לוח שנה עברי** — חגים, אירועים מותאמים, משימות לכל חג
- **CRM** — מעגלי קרבה, יעדים, יומן פגישות, ביקורי בית
- **דוחות** — ניתוח תרומות לפי אמצעי תשלום ותקופה
- **פוסטר שבת** — מודעת זמנים שבועית, בעברית / רוסית / אנגלית
- **עוזר תוכן** — מכין הנחיה מוכנה לכתיבת פוסט לרשתות, מותאמת לקהל ולשפה שהגדרת

## התקנה למשתמש חדש (5 דקות)

1. פותחים את האפליקציה — נפתח אשף הגדרה.
2. **פרטי הארגון** — שם, שם קצר, שם החותם על מכתבי תודה.
3. **מיקום ומנהג** — עיר (האשף מאתר קואורדינטות אוטומטית), כתובת, כמה דקות לפני השקיעה מדליקים נרות.
4. **חיבור הנתונים** — האשף מוליך צעד-אחר-צעד: פותחים גיליון Google חדש, מדביקים את הסקריפט (כפתור "העתק את הקוד"), מריצים `setupSheet`, מפרסמים כ-Web App, ומדביקים את הכתובת. יש כפתור "בדוק חיבור".
5. **תוכן ופרסום** — קהל היעד ושפת הפרסומים.

אפשר לשנות הכל בכל רגע: **הגדרות ← הארגון שלי ← ערוך פרטי ארגון**.

## איפה יושבים הנתונים

| מה | איפה |
|---|---|
| אנשי קשר, תרומות, מפגשים, הוראות קבע | גיליון Google הפרטי של המשתמש |
| נתוני CRM, אירועים, משימות, היסטוריה | אותו גיליון, בלשונית "סנכרון נתונים" (JSON) |
| הגדרות הארגון, העדפות תצוגה | localStorage בדפדפן של המשתמש |

אין שרת ואין מסד נתונים מרכזי. מי שמארח את האפליקציה לא רואה ולא מחזיק שום נתון של המשתמשים.

## שני עקרונות שמונעים את רוב הבאגים

**לכל שורה ביומן יש מזהה ייחודי.** תרומה מספק סליקה נושאת את מספר האישור שלו,
חיוב הוראת קבע נושא `hk:<מספר ההוראה>:<שנה-חודש>`, ייבוא נושא תווית ייבוא.
לפני כל כתיבה בודקים אם המזהה קיים. **אי אפשר ליצור כפילות**, ולכן אין ולא
צריכות להיות פונקציות ניקוי — הן קיימות רק כדי לתקן נזק שלא היה צריך להיווצר.

**"כמה חיובים נותרו" מחושב ולא מאוחסן.** מספר התשלומים פחות מספר החיובים
שכבר קיימים ביומן. מונה ששמור בגיליון יורד ולא עולה, וכל מחיקה, כשל חיוב או
ריצה כפולה מוציאים אותו מסנכרון לצמיתות. חישוב מתקן את עצמו בכל קריאה.

מאותה סיבה, חיוב שנכשל **מסומן** בעמודת "סטטוס" ולא נמחק: הוא יוצא מהכסף
ומספירת החיובים, והחודש הזה ייווצר שוב בהרצה הבאה — בדיוק כמו במציאות.

**וכל חיובי הוראות הקבע נוחתים באותו יומן** כמו כל תרומה אחרת. בלשונית נפרדת
הם לא נספרים בדוחות, וזה עלול להסתיר חלק ניכר מההכנסות.

## יומן משולב

לשונית `יומן תרומות ומפגשים` מחזיקה את שניהם באותה שורה: עמודות התרומה
(תאריך, סכום, ייעוד, אפיק גבייה) ועמודות המפגש (תאריך, מיקום, מטרה, סיכום).
שורה יכולה להיות תרומה בלבד, מפגש בלבד, או תרומה שניתנה בפגישה. הדוחות,
מעקב הקשר וזיהוי אנשי קשר "מתקררים" כולם נשענים על המבנה הזה.

## מעבר מגיליון קיים

מי שכבר עובד עם גרסה ישנה: אחרי `setupSheet` מריצים `migrateFromLegacy`.
היא מעבירה אנשי קשר, יומן, הוראות קבע, חיובים שבוצעו, כשלים, מיפוי שמות
ונתוני האפליקציה — ואז משלימה חיובים חסרים. בטוחה להרצה חוזרת, והלשוניות
הישנות נשארות במקומן עד שמוודאים שהכל תקין.

## מחסנית טכנולוגית

React 19 · TypeScript · Tailwind 4 · Vite 6 · Leaflet · Hebcal API · Google Apps Script

האפליקציה היא אתר סטטי טהור — `npm run build` מייצר תיקיית `dist/` שאפשר להעלות לכל אחסון סטטי (GitHub Pages, Netlify, Cloudflare Pages).

## פיתוח מקומי

```bash
npm install
npm run dev      # מריץ על http://localhost:5173
npm run lint     # בדיקת טיפוסים
npm run build    # בנייה ל-dist/
```

`npm run dev` ו-`npm run build` מריצים אוטומטית `scripts/sync-apps-script.mjs`, שמעתיק את
[`google-apps-script/Code.gs`](google-apps-script/Code.gs) אל `public/apps-script.txt` — משם אשף
ההגדרה מגיש אותו למשתמש. **כל שינוי בסקריפט צריך להיעשות ב-`Code.gs`**, לא בקובץ שבתוך `public`.

## מפת הקוד

```
src/
  lib/orgConfig.ts            ← לב הגרסה הגנרית: כל מה שהיה פעם קשיח
  lib/posterI18n.ts           ← תרגומי הפוסטר (he / ru / en)
  lib/api.ts                  ← תקשורת עם ה-Apps Script; קורא את הכתובת מ-orgConfig
  components/SetupWizard.tsx  ← אשף ההגדרה הראשוני
google-apps-script/Code.gs    ← כל צד השרת, כולל setupSheet שבונה את הגיליון
```

**כלל אחד לתחזוקה:** אף קובץ באפליקציה לא כותב שם ארגון, עיר או כתובת שרת בעצמו. הכל עובר דרך `getOrg()`.

## הרחבת הגיליון

אפשר להוסיף עמודות משלכם בסוף כל לשונית — האפליקציה מציגה כל עמודה שהיא לא מכירה
ככרטיסייה חופשית בפרופיל איש הקשר. אין צורך לשנות קוד. אל תשנו את שמות העמודות
הקיימות: הסקריפט מזהה אותן לפי השם.

## הוספת שפה לפוסטר

מוסיפים מפתח למילון `POSTER_TEXT` ב-`src/lib/posterI18n.ts` ומרחיבים את `OrgConfig['posterLang']`.

## אבטחה

ה-Web App של הסקריפט מפורסם עם `Who has access: Anyone` — כלומר כל מי שמחזיק בכתובת הארוכה
והאקראית יכול לקרוא ולכתוב לגיליון. זו המגבלה של Apps Script בלי OAuth, והכתובת אינה מיועדת
לפרסום. אם היא דלפה, `Deploy` חדש ייצור כתובת חדשה והישנה תפסיק לעבוד.
